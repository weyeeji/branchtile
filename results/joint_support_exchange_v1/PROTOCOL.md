# Frozen CPU-only joint-support exchange screen v1

This is a conservative falsification screen, not a new algorithm, attention-output validation, task-quality result, memory-capacity saving or speedup result. The companion `protocol.json` freezes all input hashes and parameters before natural-data computation. The three inputs are the corrected official main-model TP2 `suffix_v2` exports for docfinqa256, publicdev1 and publicdev6, rank 0, layer 15. Every natural request and both KV heads are included. Old exports containing document-Q backfill are excluded.

For each document, budget 4096/16384 and KV head, start from the supplied independent protected top-k mask. Preserve its exact cardinality, first four and last 32 document positions. For epsilon in `[0, 0.001, 0.005, 0.01]`, run request order ascending and descending separately, each with at most two rounds. No order is selected after seeing the results.

At each request turn, refresh owner counts. Sort currently exclusive unprotected selected tokens by increasing score, tie-breaking on increasing token ID. Sort currently unselected tokens already selected by another request by decreasing score, also tie-breaking on increasing token ID. Pair these lists and accept their longest cumulative-loss prefix that fits the remaining loss allowance. The allowance is epsilon times the **original** independently retained pooled-score sum for that request/head. It is never reset between rounds. Requests/heads cannot compensate for another's loss. Exact input-score equality is required for every accepted epsilon-zero swap, and final retained score must equal the original exactly. Final score totals use float64 `math.fsum`; an over-limit final total shortens the batch rather than relaxing the threshold. Owners refresh after each request batch. A no-swap round may stop early.

Score ties, unchanged masks and no feasible exchanges are valid outcomes. The original masks are checked to be top-k among unprotected positions; any violation is an input/implementation failure, not permission to change the protocol. `common_max` and `common_mean` select one shared mask from the unnormalized per-request score maximum/mean with the same budget and protected positions. They are formula controls, not a claimed QuoKA reproduction, and are not assumed to satisfy the exchange loss bound.

Primary geometry is restricted to the metadata's actual common-source document interval. The protected partial-page document tail has per-request backing and is reported separately, not merged by logical token ID. Full-document logical statistics are supplementary. N64 metrics are: fixed-union tiles `ceil(union/64)`; owner-partition tiles `sum_owner ceil(owner_count/64)`; owner-query slots `sum_owner popcount(owner)*ceil(owner_count/64)`; and independent tiles `sum_request ceil(selected_count/64)`. These are logical counters, not kernel time estimates. Full original source caches remain retained: physical-capacity bytes released are zero.

The script reads only metadata and the frozen `selector_q*_l15.pt` files. It consumes pooled scores, supports and suffix-position provenance, but does not use observation-Q values. It never opens source-KV or step 16/64/256 decode/ready Q files. No future query is used to select or validate masks in this phase. Per-request scores, union and all owner states, tile counters, deterministic selected-index hashes, exchange traces, CPU times and process RSS are retained. Peak RSS is the process-wide Linux high-water mark, including Python/Torch import overhead, not an isolated per-variant allocation. Array-byte counts are partial state accounting, not total process memory. Timing is a single CPU run, not a benchmark distribution.

The expected result is 132 rows: 3 documents × 2 budgets × 2 heads × (independent + max + mean + 4 epsilons × 2 orders). All rows and per-request losses are reported, including failed common-mask controls. A descriptive 15% union-reduction counter is frozen for screening; it does not predict speed or permit quality loss. Only a meaningful logical signal at epsilon at most 1% could motivate a separately authorized O/LSE and natural-generation check. Novelty and task-quality gates remain unmet regardless of this result.

Run from the repository using the ordinary user and project virtual environment:

```bash
CUDA_VISIBLE_DEVICES='' .venv/bin/python scripts/probe_joint_support_exchange.py --self-test
CUDA_VISIBLE_DEVICES='' .venv/bin/python scripts/probe_joint_support_exchange.py
```

The script hides all GPUs before importing Torch, uses one Torch CPU thread, asserts non-root/venv execution and asserts that CUDA stays uninitialized. It refuses to overwrite `results.jsonl`. Self-tests check exact ties, strict score gaps, a positive-loss boundary, owner counts and preservation of common-mask anchors. The schema/protocol commit must precede the natural-data run; subsequent fixes, if needed, must be reported explicitly.
