# Owner-task host guard identity correction

The initial host guard compared only metadata Tensor `_version` values. Replacing `plan.row_map`, `offsets` or `counts` with a new version-zero Tensor, or replacing `op.plan` with another plan of matching version counters, could pass validation while the task descriptors/merge table still described the original topology. This was a real correctness defect in host validation, independent of the producer/merge arithmetic.

The corrected constructor retains strong references to the original plan and its Indices/offsets/counts/row_map Tensors. Before a normal host call, validation checks the plan identity; each Tensor's identity, data pointer, shape, strides, storage offset, device and dtype; metadata version counters; and batch/GQA/rows/owner labels. An original Indices Tensor may change values in place. Replacing it, changing its layout/storage, or changing the topology requires constructing a new Attention and recapturing the CUDA graph.

CPU regression uses the actual source methods and real Torch CPU Tensors. Nineteen changed-state cases are rejected, including same-version replacement, a same-pointer view replacement, layout/storage changes and plan replacement. Original Indices in-place changes pass. CUDA remains uninitialized. The existing 26-case, 1,456-query-row CPU coverage/packing/FP64 streamed-merge checks also pass after the fix. An independent agent reproduced the old failure and verified the corrected guard using real CPU Tensors. No GPU qualification or performance claim follows from these CPU checks; the producer, merge and task planner are unchanged.

This guard checks identity/layout/version metadata, not a checksum of Tensor contents. Writes through `.data` aliases that do not advance the original version counter, or writes from device kernels, remain outside automatic host detection. External `graph.replay()` also bypasses the host check entirely. Callers must keep the topology immutable, rebuild descriptors and recapture after topology changes, and never treat the guard as content-integrity protection. Timed benchmark graphs therefore use one immutable owner topology; complete preparation cost is reported separately.

Evidence is retained in `results/operator_owner_tasks_guard_cpu_v1/qualification.json` and `results/operator_owner_tasks_cpu_v2_guard/qualification.json`. Earlier qualification artifacts are preserved.
