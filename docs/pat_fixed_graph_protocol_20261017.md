# Matched graph test of locally repaired PAT

PAT must not be assumed incompatible with CUDA Graphs merely because its wrapper creates streams/events. NVIDIA documents cross-stream capture through recorded events, waits and joining child streams back to the origin stream. The v4 compatibility wrapper has those explicit dependencies. Actual support for its full allocation and stream-destruction path still requires a runtime test; this protocol attempts it and preserves any failure. [NVIDIA CUDA Graphs, cross-stream dependencies](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html#cross-stream-dependencies-and-events)

`build_pat_fixed_graph_v1.py` copies the qualified performance source and adds only read-only metadata bindings. Its allocation path, fixed scheduler and all four CUDA objects are unchanged. There are no NaN fills or retained temporary references. The metadata visibility is needed to test graph input updates at fixed addresses; it is not part of timed execution. CPU compilation hides GPUs and does not import FlashInfer.

`benchmark_pat_fixed_scheduler_graph_v1.py` captures the complete native XQA, native AA, repaired PAT and grouped-hint RawPair calls separately on one nondefault caller stream. It allows no eager fallback for a failed graph capture. PAT temporary allocations become capture setup/private-pool behavior, just as other capture setup is excluded from replay time; all actual forward/gather kernels remain in the graph. Each arm's setup wall time is recorded. This directly tests whether the eager advantage was mainly host launch/stream overhead.

The numerical gate first replays the original captured state30 times. It then reuses the same graphs and pointers for a controlled query-row permutation, a one-token truncation of one request's existing real history, and restoration of the original Q/lengths. The permutation is explicitly not claimed to be a real next-step query. For truncation, the harness locates the unique private CTA containing that row's final token, verifies uniqueness, and decreases only its GPU `kv_in_CTA` count plus the native aliased sequence length. It changes neither pages, tree topology, split ranks nor allocation extents. Every case must match the FP64 reference, native AA/RawPair must match native bits, and every graph arm must match its own eager execution bits.

This does not establish arbitrary dynamic replanning or growth beyond assigned pages. It is a fixed-topology graph qualification. Matched timing, if admitted, uses the same randomized hot/cold paired protocol as eager, but all arms replay graphs. The initial prepared two-job manifest tests the two original real B8 captures in multistream mode; no GPU is launched by preparation. Capture errors and numerical errors terminate and preserve the failed record instead of switching PAT back to eager.
