# PQ-HSA / HiSparse 一手资料与源码审查（2026-10-16）

结论：**PQ-HSA 值得补为小预算质量的强对照，尚不是本项目的新 idea；HiSparse 已覆盖“全量 KV 可恢复、GPU 只保留有限工作集”的核心主张。** 本轮仅下载、阅读公开资料，没有 import/安装/执行第三方实现，没有使用 GPU，也没有改正式评测。以下源码判断是静态证据，不是兼容性或性能实测。

PQ-HSA 固定官方仓库 commit `dbdcc7c13868a90b3d223383974787b34c0163ca`（提交日期 2026-09-26）；HiSparse 固定 SGLang 截至审查日提交 `2adc76ad61a9c036304716a4548093b1b27b10fb`（2026-10-16 09:55:25 UTC）。逐文件 SHA-256、下载地址及审查范围见 [metadata](../results/pqhsa_hisparse_primary_audit_20261016/metadata.json)。源码放在被 git 忽略的 `data/external/`，未纳入项目依赖。

## PQ-HSA：有价值的是强基线与质量机制检验

论文用每步 decode Q 的 PQ 近似分数选精确 KV，同时用遗漏项的近似 logits 与分组 value 均值补背景；它改变 attention，不是固定 mask 的精确算子。论文的 Qwen3-30B 128K、2% paged attention 比 dense 为 **0.92×**；摘要加速不能外推到本项目。Llama8B/128K/H20 全层索引构建报告 batched 0.84 s、逐头 6.53 s。上述均是作者报告，未在此复现。[论文 v1，§3、§4、附录 C](https://arxiv.org/html/2609.33746v1)

最小后续机会是**复核已有机制是否解释本项目小预算损失**：在冻结开发样本上比较同一 PQ selector 的 truncation 与 background，并与 dense、独立 QC 分开；完整私有前缀/生成尾部必须保留。先验证实际公式/数值与 dtype，再跑自然 EOS 质量；FP64 单层误差或 pooled mass 不能替代任务质量。索引共享至多是待验证的集成优化：必须先证明相同物理前缀 K/V 的索引复用及私有增量隔离，再计完整生命周期收益；本审查没有发现足以单独宣称新颖性的机制。

## HiSparse：新颖性约束强，公开部署范围需分清

HiSparse 将完整 KV 放主存、GPU 保留有界缓存，按选择结果做 LRU/miss fetch；其“精确”相对于给定稀疏选择，不保证恢复 dense 质量。论文涵盖 Quest/Qwen3-30B-A3B-Thinking-2507 与 colocated 测量，也承认非容量瓶颈时 IO 可使其不利。因此全量可恢复、有限 residency、按需搬运和跨层预取这些概念均不是本项目新贡献。[论文 v1，§3–5、附录 A](https://arxiv.org/html/2608.07009v1)

**公开产品覆盖比论文实验范围窄。** 固定 SGLang commit 的 `validate_hisparse` 明确只接受 DSA、DeepSeek V4、MiniMax M3，并要求关闭 radix cache；当前指南要求 PD disaggregation。因此不能称现成开关已支持本项目 Qwen3 GQA + 多问题共同 prefix。[模型/缓存校验源码](https://github.com/sgl-project/sglang/blob/2adc76ad61a9c036304716a4548093b1b27b10fb/python/sglang/srt/arg_groups/hisparse_hook.py#L104)、[固定版本指南](https://github.com/sgl-project/sglang/blob/2adc76ad61a9c036304716a4548093b1b27b10fb/docs/docs/advanced_features/hisparse_guide.mdx)

指南已经明确 GLM DSA 在 SM120/121 的 FP8 KV 可用 `flashinfer_sparse_mla`，不能继续泛称 HiSparse 未支持 SM120；该声明仍不是 Qwen GQA/BF16/TP2 资格。共享 index 的跨层 prefetch 也依赖模型先提供共享选择。后续若转 residency，需实测实际 HBM 释放、host 容量、传输和生命周期成本，并保留对原 sparse 规则的正确性；本轮没有验证任何部署。[官方指南](https://docs.sglang.io/docs/advanced_features/hisparse_guide)
