# Joint selection：继续还是停止的独立决策

日期：2026-10-16。范围：基于当前冻结结果的研究决策；本次不运行 GPU、不重做综述、不读取事实审阅文件。质量状态采用主任务给出的“两份文档上表现不稳定”结论，不作独立复核。

**建议：暂不提出新算法或系统收益主张；仅保留一次有界的“低选择成本能否换来原生 E0 净收益”检验。** 算法可归入经典优化，并不排除应用或系统论文。可投稿价值必须来自得到验证的实际问题、有效机制及可推广的证据，不能由新的场景名称或局部 union 数字代替。目前尚未满足这些要求。

## 1. 证据改变了什么

在三份文档、两个预算、两个 KV head 的冻结筛查中，1% pooled-score 损失约束下，singleton exchange 的 union 缩减中位数约 19.5–20.2%，独立最短前缀剪尾约 2.8%；后者允许每请求少于 k，执行工作量也随之下降，不能仅按 union 排名淘汰。[exchange](../results/joint_support_exchange_v1/README.md)、[独立剪尾](../results/joint_support_relaxed_prefix_v1/README.md)

新完成的经典 saturated greedy cover 在相同 12 个 1% 单元中缩减 **19.91–23.83%，中位数 21.08%**，对 exchange 的两种顺序分别都是 12/12 更小。全部正 epsilon 下分别 35/36 更小，剩余单元只多 7 个 token；也优于两个 reverse-delete 起点的全部 36 个对应单元。这否定了已证明 exchange 选择效果更好的说法，但没有否定快速近似的实用价值。cover 全轮约 47 秒、exchange 全轮约 2.46 秒的任务构成不同，**不是严谨的算法速度比**；需要同输入、同计时边界的逐配置成本。[cover 汇总](../results/saturated_greedy_cover_v1/summary.json)、[reverse-delete](../results/joint_support_reverse_delete_v1/README.md)

同时必须保留四项负证据：原动态执行亏损；native union 整体仍慢于 E0；相同 k 的 E0 读取条目数量和注意力算术量未下降；完整源 KV 仍存活，**可兑现容量释放为零**。1% pooled-score 约束也不是 1% attention 或任务质量保证：已有真实 Q/K/V 复核出现约 6.5 个百分点的 attention mass 下降及明显的单头输出误差尾部。[FP64 复核](../results/joint_attention_fp64_v1/README.md) 这些相关 head/请求单元不能计成独立文档样本。

## 2. 最小可证伪机制

只检验一个具体假设：**在现有批量 native E0 内，联合选择让不同请求访问更多相同物理 KV 地址，从而减少实际访存代价，且节约量足以覆盖额外选择与索引成本。** 使用相同原始 KV backing、每请求 k、保护项、原位置、执行器与计划规则，只改变经过验证的支持集。它没有容量收益；硬件缓存是否兑现复用是待验证假设，union 下降本身不是证明。

首轮不新增 allocator、不延迟请求等待凑组、不移植 union kernel、不进行新布局搜索。只用已经共同 ready 的真实请求组。若必须引入生命周期重写或新执行器才能出现收益，就超出了本次检验，应停止这一分支，另立完整研究问题。现有两个不稳定的质量结果也不能用于挑出“看起来最好”的 epsilon；没有通过预定质量门槛时，重放只能称机制诊断。

## 3. 必须测量的最小闭环

1. **同边界成本对照。** 固定输入及排序复用规则，记录 independent、exchange、经典 cover、reverse-delete 与允许少于 k 的独立剪尾的逐配置 selector、主机/设备传输、索引构建和计划开销；同时报告 union 与总选中条目数。不要把某算法的共同排序免费复用、另一个重复排序。先用原生 E0 执行各自支持，再把 native union 作为附加对照；主要比较对象始终是最快合格的独立路径。
2. **可靠的执行差异。** 用已纠正 suffix-only 的自然 B3/B4 输入和冻结预算，逐层资格化新 mask 的 E0 对参考输出，保留私有文档尾部及后续 private KV。先固定 Q/K/V 做配对交错计时并做 A/A 控制，随后按真实层序和工作集重放；单层重复热缓存不能代表整模型。计时包括必要索引更新与完整调用。没有可用硬件计数器时只报告延迟、工作集和受控冷热现象，不能声称测到了 DRAM bytes 或 L2 命中率。
3. **摊销与质量分别过关。** 令额外准备成本为 `ΔP`，同长度每步节省为 `δt`；仅当 `δt>0` 才有 `N_break_even=ΔP/δt`。对 cover 与快速 heuristic 都计算，并与真实自然输出长度比较。层级 attention 收益先按其整步占比给出可达收益上界，再决定是否跑应用。固定长度或 teacher-forced 测量用于定位成本；自然 EOS/cap 输出用于报告完整时延、长度和预定逐题质量，不能把少生成 token 算作执行器加速。质量通过才允许提出有用的成本—质量折中。

## 4. 什么可能成为贡献，什么仍是普通组合

若小成本 heuristic 在已冻结质量要求下，比 classical cover 和独立剪尾取得更好的**完整成本**，并能解释何种自然请求重叠、工作集大小与生成长度使收益成立，这可以形成应用/系统研究的起点；不要求算法必须脱离经典优化类别。但仅证明 heuristic 更快、或某个热缓存点更快，仍不足以支撑论文。至少还需要独立文档上的复现、关键条件的反例和适用边界；当前单一 5090 架构不能支持一般硬件定律。

多 Q 聚合公共集合已有 [QuoKA，2026-02](https://arxiv.org/html/2602.08722v1#S3.SS3)；shared/private 分解和低重要性私有项裁剪已有 [QUILT，2026-10](https://arxiv.org/html/2610.11134v1#S3.SS4)；压缩副本、共享源引用和回收约束已有 [Zipage，2026-03](https://arxiv.org/html/2603.08743v1#S4.SS4)。把经典 cover/交换接到这些机制上，不能自动声称新的选择理论、首次共享压缩或新的生命周期系统。若收益最终仅来自这些普通组合，应准确报告工程应用及有限测量，不倒推独有机制。详细先例和严格约束见[独立审查](joint_exchange_independent_review_20261016.md)。

## 5. 明确停止条件

- **执行门槛：** 在冻结自然点上，E0 改变支持后没有超过 A/A 噪声且在真实层序中可重复的正收益，停止性能分支；不改用更慢的原 union 作为分母。若最乐观摊销仍超过预定实际生成范围，或整步收益上界达不到已有项目效益门槛，同样停止，不继续全应用扩跑。
- **质量门槛：** 任何预定逐请求质量/覆盖标准不通过，不把平均 ROUGE 或 pooled-score 容差替代它；两文档先导不稳定时不宣称非劣，也不事后放宽门槛。
- **贡献门槛：** 快速 exchange 在完整成本—质量上未优于独立剪尾或经典 cover，就不以它为主方法；若仅有 union 减少而无实际时间/容量收益，结果是优化代理与真实资源脱节的负测量。可以保留这一发现，但它本身尚不等于一篇达到 ISCAS 要求的论文。

本轮建议最多一次预先冻结、总计不超过 **0.2 GPUh** 的现有执行路径诊断，再按上述门槛决定；这是后续计划上限，不是本次已运行成本或新的资源分配。停止后归档结果，不以重写缓存、增加等待策略或扩大调参范围来维持方向。
