# 全六文档重复稳定性协议

本协议在任何新增重复运行之前冻结；已经看到首次六个可行文档中的五个完成结果，尚未查看 eval14 性能。因此这不是未见数据上的新验证，也不是完全事前设计的首轮主评估。触发原因是部分文档原生 A0/A3 约10%计时变化。

对原 next8 选择中**全部六个可行文档**（eval11、12、13、14、16、18）各增加两个全新进程，分别命名 repeat1 和 repeat2。原 eval17、19 超上下文失败在每轮八文档/98题分母中原样保留。所有原问题、全文、顺序、生成 seed、8192 cap、163840 context、policy、模型、内核、离线训练资格和四阶段 natural ABBA 驱动保持冻结。只修改输出路径、任务名和可分配 GPU 对，不修改任何运行源码。

首次运行继续作为已预声明的主要结果；新增结果不替换首次，不按快慢择优，不只重复有漂移或收益大的案例。一次重复失败如实计入，不用第三次成功覆盖失败。root 按可用 GPU 对统一流水调度，研究代理只做 CPU 分析。

每个进程独立记录原生初始化、实际 production 图创建、离线资格加载核对、setup receipt 导出及全部四阶段。主净计时定义不变：原生两次 anchor+generate 均值，除以候选两次 anchor+generate 均值加本进程全部额外 setup；setup 每次都完整收费，不跨文档/重复摊销。

逐轮检查源哈希、离线资格 fingerprint、清洁终态、完整输出 token/APC/finish/stop、问题/位置图轨迹、质量、caps、preemptions 和候选执行比例。每轮报告 A0/A3 最大/最小、原始分阶段计时。跨三轮核对输入 token hash、自然输出、完整图轨迹及评分是否相同，任何不一致保留为复现问题，不归结为噪声并略过。

分析包括每轮全部六个可行文档的条件几何均值及总时间比；每文档列出三次完整比值、范围、算术均值及几何均值，同时计算三次原生均值时间除以三次含 setup 候选均值时间。三次都通过且跨轮轨迹一致的文档才进入“重复完整”的条件汇总，同时显式保留全部八个文档的覆盖和失败分母。该汇总属于补充稳定性分析，不覆盖首次主要结果。

文档是泛化统计单位；同文档三个进程用于观测运行噪声。两次 A/B、解码步、层、rank 都不是独立样本。不用这些重复构造虚假的大样本置信区间，也不把同一输入的重复说成新增未见文档。至少报告全部实际比值和范围，不根据结果调整指标、policy或选题。
