# Preserved eval2 exactness counterexample

The late same-state run in `results/raw_pair_eval2_late_same_state_v1` failed after saving four snapshots. Its final exception is a diagnostic metadata bug (`Path.stat().st_size` was mistakenly called). This does not invalidate the tensors written before the exception, and it does not make the numerical counterexample a tool-only failure. The original failed run is retained. Independent v2 scripts fix only this metadata operation.

Both ranks passed all 48 layers on 69 successive B9 states, graph indices 1786–1854. At graph 1855, rank 1 layer 0 has identical native and candidate Q but two different BF16 O elements. Native AA, public PDL on/off, the native witness, and the unshared checkpoint/resume implementation are bitwise identical. Candidate ordinary and NaN-poisoned-state replay produce the same two differences. The largest absolute error is 2.384185791015625e-7. Both elements belong to row 3, question 6, query head 1; dimensions are 20 and 58. Question 6 is also the first question with a visible token change in the original production run, 84 decode states later. This association alone does not prove that these two values caused the eventual token choice.

The difference already exists in the prefix checkpoint. Under the explicit GQA16-to-GQA8 register mapping, only row 3 / KV head 0 / split 5 differs: 256 PV accumulator floats (maximum difference 8.344650268554688e-7) and four redundant row-sum entries (maximum difference 1.52587890625e-5). All final row maxima and backward hints are identical. Thus tail continuation, final split merge, stale raw workspace, or native PDL selection are insufficient explanations. The immediate question is which producer/consumer arithmetic step inside the shared prefix first differs.

Rank 0 first differs at layer 3, where Q has already changed; its same-Q attention comparison still passes. Do not describe this as a rank-0 kernel failure. The CPU audit separately records graph 1856 snapshots left by retries after the metadata exception; those are not independent successful full-model runs.

`audit_raw_pair_same_state_snapshot_cpu.py` audits all four snapshots without initializing CUDA. The report is `results/raw_pair_eval2_late_same_state_cpu_audit_v1.json`. No tolerance is relaxed and eval2 remains failed.

`diagnose_xqa_raw_pair_snapshot.py` is the next bounded single-GPU diagnostic. It preserves native S, full page-table width, original cache stride, the actual Q/KV values, and physical sharing while compacting used physical page IDs. It checks native/public and captured outputs, scans all complete-prefix cut points for raw-state divergence, saves the first mismatching checkpoint, and tests swapping each pair's member order. It makes no performance claim and does not change the frozen CUDA kernels.
