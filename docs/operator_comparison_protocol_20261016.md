# 输出长度变化时的算子与应用比较协议

状态：CPU-only 设计规范，2026-10-16；没有启动、授权或声称完成新的 GPU 实验。
本规范用于下一版算子候选，不能改写既有实验的冻结条件或把既有开发结果升级为正式结论。

## 要回答的是两个问题

1. **同样的计算，执行得是否更快？** 固定真实输入状态做配对重放，评价算子实现。
2. **实际回答问题，是否在保持质量时更省时？** 自然 EOS、多 seed、完整分母，评价完整方法。

同 seed 能对齐问题和实验随机重复，不能保证两种精度、浮点归约顺序或后端生成同一串 token。
输出长度是方法行为的一部分。既不强迫自然答案等长，也不按答案长短筛选成功结果。

## 第一层：固定实际工作量的执行比较

### 状态和正确性

- 从冻结的开发文档和问题取得真实运行状态，记录文档/问题/模型/分词器/模板身份、
  Q、K/V、选择 mask/索引、位置、步长、物理地址共享关系、KV 精度及量化尺度。
- 对纯实现替换，每个配对样本使用完全相同的 Q/KV/mask/尾长及输出契约。
  新实现必须先通过独立参考数值检查、边界/因果 mask、共享页和私有尾部检查。
  只测裸 kernel 时与 complete call 分列；索引构造、必要输出复制和同步必须进入 complete call。
- 改变 mask、缓存精度或算法时，先分别对各自的数学输入做数值资格，再分开报告实现收益和算法变化。
  不把“不同 mask 上各算各的用时”称作同工作量纯执行收益。
- 基线自然轨迹是预先冻结的主状态源。若候选已产生自然轨迹，另做候选轨迹上的相同状态重放，
  作为轨迹选择敏感性检查；不能只挑候选最有利的状态。二者均不能代替自然质量评价。

### 覆盖自然退出后的 batch 变化

- 从自然 EOS 运行记录每一步的实际活跃问题 ID、位置、上下文/私有尾长和调度 batch；
  覆盖 B3、真实退出后的 B2、B1 以及预注册的早/中/晚步区间。
- B1/B2 必须取自真实存活请求状态。把某个 B3 快照裁成前一/两行，仅能称作形状微基准。
- 每种实现重放同一批冻结状态，保持同一状态顺序或使用预先冻结的交错随机/反向顺序。
  主报告按真实轨迹频次加权的完整链总时间，并保留每个 B/步区间结果。
  该总和是冻结轨迹上的执行估计，不是包含模型层间干扰的实测 JCT。

### 计时和统计

- 保留热态和人工清缓存的冷态两项，不能将清缓存称为真实模型层间缓存状态；
  最终还需实际完整模型集成，检验 MoE/GEMM/NCCL 干扰后的收益。
- 同 GPU pair 上交错测基线与候选，记录温度、时钟、显存和并发负载；八卡可并行运行
  四个 TP2 配对副本，不能把不同 pair 固定给不同方法后解释细微因果差异。
- 先做 A/A；若重复不是相同 token、位置和调度工作量，保留差异，不能当相同工作的测速重复平均。
- 以完整随机/反向测量 block 为 bootstrap 单位，至少 10000 次、95% 区间；
  同 block 内的重复、层、head、rank 不能扩充独立样本数。按文档/状态/设备副本保留结果。
- 报告微秒差和配对速度比。多 rank 单独计时的最大值只是 proxy；TP2 应用收益要用
  实际共同运行、请求完成边界上的 host wall time，不能把 rank-max 冒充同步 TP 关键路径。
- kernel sum 占比不等于关键路径比例；没有关键路径证据，不从该占比直接推导应用加速上界。

可选的整模型固定 token 重放/teacher forcing 可以进一步隔离执行与生成路线，
但必须单列为固定工作诊断：其 token 由冻结参考轨迹提供，不是候选的自然答案，也不是质量证据。

## 第二层：自然 EOS、质量与总成本联合比较

### 冻结和完整分母

- 开发完成后冻结候选、强基线、数据 split/cluster、模板、显存/并行度/上下文/并发限制、
  sampling 全参数、seed 列表和最大输出上限。正式质量使用至少三个成对 seed。
- 每个方法按自身概率生成，正常 EOS 停止；上限仅是共同资源限制。
  超时、OOM、无法服务、cap、解析失败、未回答全部保留；任务评分按冻结规则计入分母，
  不能事后删题、延长某方法上限，或只对两臂同时成功的子集给主结论。
- 记录每个请求输出 token 数、结束原因、质量分数、首次 token 和完成时间，
  以及每步真实活跃 batch/问题 ID。组延迟不能代替未采集的逐请求延迟。
- 同文档多问允许复用同一前缀。冷前缀与已缓存前缀服务分开；初次公共文档成本只计一次，
  明确后续复用次数。现有 q0 完整 prompt + 丢弃一 token 的 anchor 不能称纯文档 prefill。

### 成本分列与边界

每次运行同时保留以下原始量，不把分阶段计时之和伪称为已实测的单个客户端请求延迟：

| 项目 | 报告方式 |
|---|---|
| 初始化 | 进程/权重加载、JIT/编译、图捕获分别记录；并发加载受争用的耗时不称孤立初始化性能 |
| 首次文档准备 | 分词、prefill/anchor、selector、CPU/D2H/H2D、安装和必要同步；避免重复计费 |
| 在线解码 | 从统一就绪/提交边界至自然完成，包含 host 准备、实际 graph、全部层和 TP 通信 |
| 请求体验 | TTFT、各请求完成延迟、组 makespan/JCT；仅声称实际采集到的指标 |
| 资源 | 实际分配 GPU wall × 卡数、失败费用、缓存容量、进程显存峰值；不把 token 容量翻倍称显存减半 |
| 审计/导出 | 单列同步和数据复制；有测量 hooks 的结果注明，最终低开销集成验证还需单独做 |

初始化可按预先声明的复用次数摊销，并同时给零摊销/首次与稳态结果。
选集准备只有确实可提前执行且满足依赖时才允许重叠；必须测完整并发流水线，
不能简单用两段耗时的最大值替代实际延迟。

### TPOT、吞吐和 JCT 的解释

- 单请求若实测 token 发出时间为 t1...tn，n>1 时 TPOT=(tn-t1)/(n-1)，
  且该请求完成时间约为 TTFT+(n-1)×TPOT（需定义是否含最后收尾开销）。
  不采集逐 token 时间时，不能把组 wall/总 token 直接命名为 TPOT。
- batch 中总 token/组 wall 是组吞吐；其倒数不是平均用户 TPOT。
  JCT 同时受每步速度、各答案长度、退出后的 batch 变化、prefill 和调度影响。
- FP8 更短且更快，可以报告自然方法总成本下降；只有固定状态层的结果才支撑每步执行更快。
  固定工作层更快、自然层答案更长而 JCT 更慢，也必须同时报告。
- 用“最终正确答案/请求的总成本 + 质量分数 + 长度/失败分布”呈现质量与成本关系。
  不以 token/s、等长裁剪或“仅正确样本耗时”替代完整分母的主要结论。

### 自然任务统计与论文门槛

- 对相同问题和 seed 形成成对记录。先在题内合并 seed，再按冻结且有来源依据的独立
  公司/文档来源 cluster 重采样，至少 10000 次、95% 区间。seed 重复、设备重复、
  同一文档的多个问题不是新独立文档；不能把推断出的公司 ID 当已验证身份。
- 质量同时报告 question-micro 和 equal-cluster 差异。既有 2pp 非劣界沿用冻结规则，
  使用 `src/paired_statistics.py` 的退化区间保护；正式非劣还依赖完整分母和独立 cluster 审计。
- 成本采用相同 cluster 配对 draws，预先声明总成本比还是请求/cluster 平均估计量；
  不能事后切换 median-of-ratios 与 ratio-of-totals。保留失败费用，主成本不能只对成功样本计算。
- 只有质量门槛和完整成本收益同时满足，才称应用收益。当前项目的约 15% 完整算子调用
  信号和约 5% 应用净改善门槛保持不变；小规模开发结果不视为正式论文结论。

## 现有证据的边界

- `configs/native_precision_natural_development_v1.json`：两文档、六唯一问题、一个 seed，
  各臂两次 A/A；跨精度长度不同，所以只能描述自然成本/质量，不能识别纯执行收益。
- `configs/joint_real48_replay_protocol_v1.json`：实际 48 层原始 KV 和输出复制，六随机/反向 block；
  但只有单个 B3 状态，B1/B2 是行前缀，attention chain 不包含完整模型干扰，
  rank-max 是 proxy。这些限制在下一轮扩充真实退出状态前仍然成立。
- 本文只规定如何把两层证据连接起来；不追加预算、不改变失败状态，不声称已完成自然正式评价。

机器可读的对应规范：`configs/operator_comparison_protocol_v1.json`。
