# 新版本 next8：全部预声明重复终态

六个可行文档的首次运行及各两次额外重复，共18个进程，全部clean exit并通过source/fingerprint、完整token/text、APC、finish/stop、评分和图请求/位置轨迹审计。所有计划重复都保留，没有用更快值替换首次主结果；全部自然EOS，无输出cap、无记录抢占。另两个原始context失败仍在每轮8文档/98题分母中。

**结论：收益可复现，但完整任务收益较小，首次部分较高比值受运行漂移放大。**六文档的三次均值汇总，ready比值为1.085100×，计入anchor/prefill为1.056208×，再逐文档完整收费setup和导出后为 **1.043236×**，对应总任务时间减少 **4.144%**。这是六个文档各自三次平均时间相加的比值，不是18个独立文档，也不是置信区间。

## 环境事件与额外确认

18个计划进程的账本GPU分配交集为0；**这不代表不存在外部CUDA活动。** `results/cpu_visible_cuda_import_incident_20261017_v1.json`记录三个CPU指定导入测试意外初始化CUDA，未捕获PID、UTC起止、设备UUID、显存或实际GPU工作。receipt创建时间只能说明这三次命令在该时刻前结束，不能用tool elapsed倒推出精确UTC区间。

Root报告eval12重复2进程1642402可能与事件重叠，该计划值保留并在运行目录增加 `environment_uncertainty.json`。其余早于receipt的运行无法仅凭该receipt建立完整影响集合；“无法判定”不等于断言污染。eval13重复2在事件结束后启动，可排除这三次已结束导入的时间重叠，但不能据此证明所有环境条件均隔离。源/数值审计qualified也不等于环境隔离证明。

额外 `results/grouped_hint_clean_followup_v1/eval12_bf16` 在事件后完成，source、输入、全部输出/轨迹相同，主净1.037727×、ready1.126983×、AA1.004326。它单列为补充，不进入冻结18进程均值，也不替换原重复2。使用不同GPU pair且没有此前事件的精确时间信息，不能用该补充反推出此前事件影响为零或具体多少。

## 成功覆盖、首用与论文证据强度

固定选择共8文档98题，可运行并保持输出一致的是6/8文档、67/98题；两个超上下文文档及31题保留为配置失败，没有裁文、减少cap、换题或换文档。这里的速度统计仅条件于6个可行文档，不能为失败输入编造速度。

任务质量保持不变：严格16/67、rounded29/67；在全部选择98题上，已验证正确数分别为16/98、29/98。三次重复不会把正确题数乘三，也不会改善原文/标注可靠性。第二模型Thinking开发实验虽保持输出且有端到端收益，但该文档严格/rounded均0/8，不能用其速度替代任务效用证据。

Ready不含共享anchor准备；cold含文档anchor/prefill与自然生成；净cold再加候选全部额外setup。三者都不是独立冷服务启动测量。共同模型加载/原生图初始化与输入准备尚未纳入上述主比值；原始receipt里的首用组件相加估计只能标注为估计，不能当作实测冷服务加速。在线重新做严格数值资格的成本也不能隐去；当前主实验明确使用匹配source/fingerprint的离线资格和单套production图。

这些结果支持一个真实、可复现且保持当前输出的工程收益：与当前生产原生实现相比，在此长文档自然问题cohort上的端到端净改善约几个百分点，而不是仅有脱离模型的算子速度。它们尚不足以单独保证达到ISCAS论文要求：开发机制与既有共享prefix工作的区别、同能力成熟实现对照、局限输入上的解释，以及更可靠的任务效用仍决定论文说服力。不能把所有18个比值为正称为统计显著性，更不能把统计显著性当作投稿保证。

下一步组合多文档调度/可迁移dispatch证据若能证明自然任务上的额外收益，应作为新版本独立实验，不回写此次小收益或重新包装已见数据为未见测试。原生数值保持机制和算子实现证据可以构成贡献的一部分；当前结果最合适的定位是已验证的基础机制与诚实端到端下限，而不是已完成全部论文验证。
