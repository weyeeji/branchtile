# Raw shared XQA control audit after eval2

The native consumer has a request-level control dependency that is independent of its per-row final numerical state. In the installed SM120 kernel, `enableMicroFastPath` is false and `CTA_ROW_MAX_BACKWARD_METHOD` is 1. `needRescaleMask` is a warp ballot over the current query rows, and `skipAllRescale` skips an entire consumer update branch. The branch condition is shared across native GQA heads of one request. It cannot be enlarged to include packed requests without auditing its side effects.

The observed non-identity side effect is the shared-memory backward-hint write. A row's global maximum may have advanced while processing a different 64-token tile, leaving a particular producer's hint deliberately stale. If the native request's next tile needs no rescaling, it skips the hint store. A different packed request can make the old shared implementation enter that branch and overwrite the stale hint. The eval2 cutoff scan demonstrates this exact sequence: the hint first differs at cut 339; U/z first differ at cut 348; final hints later agree again. It is therefore insufficient to compare only final maxima/hints or save their values correctly at a continuation boundary.

The new grouped-hint build keeps every lane participating in the original store function and uses the previous hint as its store value whenever that lane's original request-group ballot is zero. It must use the whole original group (8 heads for the 30B TP2 model, 4 for 4B TP2), not the individual row bit. Tail modules and their request width are unchanged. METHOD4 atomic updates and other architectures are not implemented or claimed.

Two other shared branches remain visible in the source:

* Entering the outer rescale branch solely because of another request can multiply this request's accumulator and row sum by `expf(0)`. For ordinary finite represented values that scale is one, so this is an identity operation. This is an arithmetic argument, not a blanket claim about exceptional values, compiler contraction or denormal handling.
* A packed request can make the warp-wide `skipXRowRescale` false while the current request has no X rescale. That request then multiplies its BF16 probability tile by a BF16 scale of one. `xRowNeedRescaleMask` and the row-wise scales are still derived from each row. The patch does not rewrite this code. Tests must retain identical-Q raw checkpoint and final O comparisons; a later counterexample would require preserving these control paths as well.

The grouped-hint correction passes the preserved real counterexample at every one of 442 prefix cut points, native AA/PDL controls, unshared checkpoint, swapped pair members, and compute-sanitizer. This establishes the fix for the observed failure, not universal exactness. Full-model known-input regression and new unseen inputs are separate gates. Eval2 has become a regression input and must not be presented as fresh heldout evidence after this correction. Existing dispatch thresholds remain fixed; speed must be measured again for the new build.

Independent new integration files are `vllm_native_raw_pair_grouped_hint_worker.py`, `benchmark_native_raw_pair_grouped_hint_e2e.py`, `benchmark_native_raw_pair_grouped_hint_production.py`, and the late-state grouped-hint diagnostic pair. Old offline qualification receipts cannot satisfy the new worker's source fingerprints. The frozen runtime, scheduling thresholds, native implementation, and original failed outputs remain available.
