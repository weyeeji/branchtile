# PAT scratch-slot collision on the actual B8 capture

The original scheduler at `8cb067f` assigns correct physical KV tokens but incorrect partial-output split ranks for the captured train1/rank0/layer15 input. This is independent of CUDA execution: `audit_pat_schedule_slots_cpu.py` compiles the original `prefix_tree.h` in a CPU-only binding and checks the same legal page16 tile list and full original page table.

There are 253 expected `(request, split)` slots. Requests 2, 3, 4, 6 and 7 each have two writers for split 2 and no writer for split 31. Group 0, CTA 24 writes the shared block to rank 2 for all eight requests; private CTAs in groups 2/3 also write rank 2 for those five requests. Each slot expands to 16 LSE elements and 16×128 partial O elements. Gather reads all ranks below each request's `num_split_per_seq`, including the five missing slots. The physical-token multiset for every request is nevertheless exactly correct.

`balancePack` uses `split_per_seq[box.q_table[0]]` for the entire shared box after individual private subtrees have advanced their counters differently. Incrementing all members does not repair that initial mismatch. The concrete failure occurs in the later shared-box split path around original `prefix_tree.h:612`; the earlier large-box splitting path uses the same assumption. The logical slot audit does not itself prove CUDA lane-store behavior, but it establishes an invalid scheduler-to-gather contract before GPU execution.

Consequences: the explicit stream fork/join repair cannot solve overlapping writers and unwritten slots. A single-stream FP64 pass at one allocator state is insufficient to qualify this schedule; the previous matched-eager result must not be treated as a reliable PAT numerical baseline until this is repaired and requalified. This does not imply PAT's method is inherently incorrect or slow.

The independent debug artifact reuses all four compiled v4 CUDA object files without changes. Only the C++ binding/API adds NaN initialization of partial O/LSE, retains those temporary tensors, and exposes scheduler metadata. `diagnose_pat_scratch_v1.py` checks complete calls, then invokes each original MNW group alone and records which temporary slots remain NaN; isolated-group gather outputs intentionally have missing contributors and are not qualified attention outputs. No timing claim is made. Both the original single-stream option and the explicit multistream path are supported. GPU execution is pending parent scheduling.

A candidate repair is to number final boxes afresh, shared query sets before their subsets, checking that every member's next rank is identical before assigning a common CTA rank. This preserves boxes, KV token partitions and tile choices for this laminar schedule. It must reject nonlaminar/unassignable cases rather than silently introduce holes; general applicability and numerical/performance effects require separate qualification. It has not been applied here.
