# 从缓存O机会诊断到可部署结果的最小测量路径

缓存O干预证明真实模型图有可替换空间，尚未给出获得该收益的算法。后续优先验证一个可以随着每步Q变化实际算出O、随着请求退出更新支持的路径。以下是测量约束与最小证据，不是新颖性声明。

## 第一项可部署对照

以生产O-only FlashInfer/XQA为主基线，保留实际page16、原生KV物理页、全部48层/全部heads/TP2。在同一engine运行精确共享prefix的简单实现作工程对照，可使用已有固定union或标准共享prefix+private-tail+稳定merge。全history情况下prefix所有query共享，先不引入近似稀疏选择、FP8转换或新的质量损失来混淆执行收益。

该路径的价值是检查“机会能否以现成简单共享实现兑现”。共享前缀、query packing、split-KV和稳定merge都有先例；不能把原生vLLM暂时关闭cascade当成提出新算法。若简单对照已经有收益，则新机制须说明在其上额外解决了什么瓶颈。无需以47选1 oracle作为成立门槛。

## 数值与部署资格先行

1. 真实Q、真实page16 KV与每步seq_lens下，对原生O-only进行全48层资格。所有heads/request均覆盖；同一support、同一softmax尺度、同一KV精度。
2. 先固定真实状态验证，再用16步整模型固定生成捕获每层输出、hidden/logits与真实请求映射，排查private-tail/页边界/请求退出。任何数值差异若会改变自然轨迹，需要另行做任务质量评估；不能用同seed等价替代。
3. 全图必须保留KV写入、原生量化/MLP、通信。计时对照不额外计算应用不需要的LSE单位转换。候选分段归一化所需LSE属于候选自身计算成本。
4. GPU plan/metadata更新、请求首次出现与退出、重新捕获、支持重建及所有预处理均计入实际执行成本。JIT和引擎启动单列，不能隐匿首次服务准备成本。

## 最小成对整模型实验

以已冻结训练文档120.5K的B8真实题组起步，BF16原生和候选在同一engine、同一精度内比较，FP8在另一个独立engine复验。先两次原生AA确认tokens/APC/调度轨迹相等，再做随机与反向的原生/候选固定128-token和较长512-token执行。固定长度只用于工作量控制，不代替自然质量。

每条固定轨迹统计至少：完整generate墙钟、每步准备host时间、全模型图event、输出tokens、每步活跃请求及位置、APC命中、额外显存/计划容量。若候选产生不同tokens，既报告自由生成结果，也可以另做teacher-forced相同轨迹诊断；不能把后者的速度包装成自然请求结果。

## 自然EOS与退出

train1原生B8自然实验已表明，全8题共同活跃只有BF16的291步/2612总步，FP8的773步/3022总步。候选要么支持B7…B1的动态收缩，要么明确在小batch回退原生，同时计入切换成本。只在B8固定图快、在退出后慢的方案未必有完整请求收益。

自然对照分别报告共享文档anchor、整组生成walltime、二者总和、每题答案与长度/stop、各batch存活步数，不截断答案对齐长度。至少在未用于调参的新文档确认正收益，再扩seed和更多文档做质量/延迟统计。当前已有单例不能给出p95或质量非劣结论。

## 何时继续优化

优先根据同任务、同精度真实端到端结果和剩余瓶颈决定，不能仅因某个算子胜过弱对照或cacheO诊断大而扩跑。若简单共享实现已经显著有效，研究重点是有明确技术增量的低开销可部署机制；若连简单共享在实际存活期内也亏损，则调整场景/机制，并把负证据保留。ISCAS投稿价值最终需由清晰问题、新增机制、充分对照和可复现实验共同支持，没有单一预设速度比可以代替这些条件。
