# Joint E0：48 层检查前的独立摊销决策

日期：2026-10-16。本次只读开发数据、源码和原提案；CPU 计算，不运行 GPU，不访问正式 eval100 或事实审阅文件，不修改主任务台账。

**判断：现有证据不足以支持完整应用扩跑，当前实现的准备成本尤其不利。已预冻的单次真实 48 层检查可以作为封顶的机制判别，解决单层 forced-cold 信号能否存在于真实 KV 布局的问题；它不能被当作通过研究推进门槛。** 不因这次检查扩大模型、预算或调参范围。

## 1. 先固定计量口径

[原提案 §六](../proposal-iscas.md) 将完整 attention call 的目标写为 **1.15–1.4×**，首轮要求约 15% 且超过 **A/A 两倍噪声**的稳定完整调用信号，再投完整集成；完整文档组目标是同质量下 **5%–10% JCT 降低**。这些是项目推进目标，不是会议录用门槛。`1.15×` 对应延迟降低 13.04%，不是 15%；后续同时报告速度比和延迟变化，保留原门槛，不能选择一种口径让边缘点过线。joint 改变 mask，因而还需单独证明选择质量，不能把原同 mask 算子资格移植成质量保证。

[单层 gate](../results/joint_e0_gate_v1/README.md) 的 primary BH/O-only complete-call 热速度比为 **0.9981–1.0150**；16K 冷速度比分别为 **1.0714、1.1538、1.1250**，即延迟减少约 **6.67%、13.33%、11.11%**。冷时间集中在 2.048 μs 的重复档位，部分区间退化，且尚无独立重跑/换卡验证。一个 forced-cold 点接近 1.15× 不等于稳定推进信号。144 数值资格与 3,840 配对记录也不等于大量独立文档。

另有重要配置差别：gate 是 4K/16K、单层连续 export；[48 层 qualification](../results/main30b_sparse/joint_selector_graph_qualification_retry1/preparation_summary.json) 是 **32K、一份文档、B3、真实 TP2 cache**。下文外推只用于敏感性估算，绝非已测应用收益或严格硬件上界。

## 2. 当前单个配置的准备成本应如何记

48 层原始准备记录如下；D2H 已含于 selector freeze，计总时间时只能加一次。

| 项目 | rank0 | rank1 |
| --- | ---: | ---: |
| score D2H 与 CPU copy | 0.03420 s | 0.03410 s |
| epsilon=0 的 finalize | 2.46537 s | 2.48854 s |
| epsilon=0.001 的 finalize | 2.79014 s | 2.87674 s |
| epsilon=0.01 的 finalize | 2.74394 s | 2.77360 s |
| epsilon=0.01 的全层 union 缩减 | 9.13% | 9.89% |

1% 单配置的 `max_rank(finalize+D2H)` 为 **2.80770 s**，0.1% 为 **2.91084 s**。这是当前实现的准备成本代理，尚未含额外 RPC 等费用；TP 两 rank 并行时不能简单相加，实际服务关键路径仍需测量。不能把三个 epsilon 的约 8.3 s 全部算到部署一个 epsilon，也不能把 epsilon=0 的约 2.49 s 从正 epsilon 中直接扣掉：独立路径未做这套 joint finalize，epsilon=0 是资格控制而非原基线的必需开销。

安装 history 在候选与 independent 臂均约 0.65–0.68 s；这部分不能全部归为 joint 增量，也不能把未配对的细小差异视为节省。移除重复验证、加速普通 CPU 处理有工程空间，但在新实现资格和公平计时前，不能用假设中的低成本替代实测。不同问题组产生不同分数和 masks；仅复用文档 prefix，**不允许把 query-conditioned finalize 任意除以 4 或 16 个新组**。完整源 KV 仍保活，容量收益为零。

## 3. 批量步数决定摊销，不是总输出 token 数

设 `P` 为一次额外准备、`δ_t` 为第 t 个 decode 步在 TP 关键路径上的实际节省。必要条件是 `Σδ_t > P`；5% 应用目标需要 `Σδ_t ≥ P + 0.05 T_baseline`。48 层、两 rank 的各 kernel 时间不能机械相加成 TP JCT 节省。

为说明量级，**假设**每层每步都节省相同时间，取 `P=2.80770 s`：

| 假设单层节省 | 48 层每步节省 | 仅回本所需批量步数 |
| --- | ---: | ---: |
| 热点最大两个独立中位数之差 0.2248 μs | 10.7904 μs | 约 260,203 |
| 冷档差 2.048 μs | 98.304 μs | 约 28,561 |
| 冷档差 4.096 μs | 196.608 μs | 约 14,281 |

上述绝对差不是配对置信区间，更不能拿一个最佳层代表其余 47 层。即便暂按此乐观外推，3,000–12,000 个三题合计 token 也仅相当于约 1,000–4,000 个 B3 等效步；若实际共同存活 N 为 1,000/2,000/4,000，仅回本分别要求 **2.808/1.404/0.702 ms 每完整 48 层步**，即平均每层 **58.49/29.25/14.62 μs**。

实际已有同栈 E0 的 32K 自然长度更具体：只读取 output token 计数，没有读取答案文本。下表用每题最短长度作为共同 B3 步数的乐观上限；首 token 来自 prefill 时还须扣除。`Σtokens/3` 仅是等效量，不能代替 alive 轨迹。

| 开发输入 | E0 三题长度 | B3 步上限 | 回本所需 48 层步节省 | 达到 5% 所需步节省 |
| --- | --- | ---: | ---: | ---: |
| original / 32K | 1144、1138、1140 | 1138 | 2.467 ms | 3.363 ms |
| publicdev1 / 32K | 4003、1774、1883 | 1774 | 1.583 ms | 2.721 ms |

来源：[开发汇总](../results/main30b_sparse/fi_natural_expansion_summary.json)及其中 `fi_natural_original_b32768/summary.json`、`fi_natural_publicdev1_b32768/summary.json` 的 E0 token 长度。5% 列暂用 anchor+generation **20.3896/40.3922 s**，尚非含全部 selector/初始化的完整 JCT，是有意偏乐观的必要门槛；它假设收益仅在共同 B3 阶段，其余阶段未给收益信用。B2 需另测，B1 已无跨请求复用，不能继续套 B3 收益；若某阶段有回退或倒退也要计入。

甚至把 4.096 μs/layer 的节省假定延续到最长请求、包括 B1，两个例子的总毛节省也仅 **0.225/0.787 s**，尚未付 P，且仅相当于 generation-only 时间的 **2.34%/2.71%**。这是反映当前信号量级的条件情景，不是对未来真实 32K/48 层结果的证明。另一个 union 自然输出的 12,139 tokens 不能借作 E0 的摊销机会，更不能靠输出变长改善盈亏表。

## 4. 对已经预冻的 48 层检查，建议采用的最小判据

1. **先看能否推翻成本判断。** 必须报告原生完整 48 层调用的绝对时间和配对 `Δμs`，而非只报百分比。若在观测 alive 范围内，即便乐观累加也支付不了当前 P，停止当前实现的应用分支。若想主张更快 selector，应先实现并独立测量新 P；不把 epsilon=0 差额当作已实现优化。
2. **推进门槛维持原约定。** 可分辨的 1%–2% 小收益如实保留，但不因此降低约 15%、大于两倍 A/A 噪声的完整调用推进门槛。forced-cold、单卡一次区间或计时档位不能作为稳定性证明。真实 48 层 attention 图也仍缺少 MoE/GEMM、TP 通信和自然退出的交错，不能直接写成整模型加速。
3. **应用必须有 5% 净收益空间。** 后续只在冻结质量要求能够通过、且公平成本下 `Σδ_t−P ≥ 0.05 T_baseline` 有可信余量时考虑最小应用确认。即使 attention 约 1.15×，其总时间占比 f 也需满足 `f(1−1/1.15)−P/T_baseline ≥ 0.05`；当 P=0 时仍需 f≥38.33%，准备成本只会提高所需占比。该近似不替代自然 JCT 测量。

因此，本次 48 层测量的价值主要是**结束 forced-cold 归因的不确定性**，不是现有数据已经给出了值得扩大投入的完整收益前景。若信号仍停留在几个 μs/layer，或仅依靠未实现的准备优化才能回本，应按原标准停止并归档，保留真实小收益与负结果，不扩成缓存系统重写。
